# v0.7 — บ้านที่อยากกลับมา

## สิ่งที่เล่นได้
- ตั้งชื่อหมู่บ้านและชาวบ้าน 5 ชื่อ (เปลี่ยนเฉพาะคนที่ย้ายเข้ามาแล้ว)
- ย้ายอาคารฟรี ไม่ตัดทรัพยากรหรือเปลี่ยนจำนวนงาน/ที่พัก แปลงยังต้องริมน้ำ ค่ายตัดไม้ยังต้องใกล้ป่า
- ของแต่ง 5 แบบ: ดอกไม้ ต้นไม้ ทางเดิน ม้านั่ง โคมดินเผา ใช้ชั้นตกแต่งแยกจากอาคาร พื้นที่ละชิ้น
- เก็บของแต่งคืนวัสดุเต็มจำนวน ของแต่งไม่เพิ่มผลผลิต/คะแนน
- คำขอ 3 เรื่อง ไม่มีหมดอายุ: ดอกไม้หน้าที่พัก, มื้ออาหารร่วมกัน, ของขวัญจากเตาเผา
- รางวัลคำขอรับครั้งเดียว ม้านั่งและโคมไฟเปิดผ่านคำขอ อาหารส่งมอบถูกหักจริง
- แสดงสถานะอาคารและปุ่มไปงานที่เกี่ยวข้อง: ขาดคน ขาดน้ำ ขาดสูตร/วัสดุ หรือพร้อมใช้งาน
- เป้าหมายงานเลี้ยงฤดูหนาว ไม่มีเส้นตายและไม่มีบทลงโทษเมื่อไม่เข้าเกม กติกาความพร้อมเดิมยังใช้
- คนมีชื่อ แต่การแบ่งงานยังเป็นทีม ยังไม่มีบุคลิก ความสัมพันธ์ หรือ pathfinding รายบุคคล

## เซฟและการย้ายข้อมูล
- อ่านเซฟ v0.6 จาก `paperbound-village-v1` แล้วเติมชื่อ/ของแต่ง/คำขอเริ่มต้น โดยรักษาทรัพยากร อาคาร วัน สูตร คนและงาน
- บันทึกใหม่ใน `paperbound-village-v2` เป็น envelope `{format, villageId, revision, updatedAt, state}`
- `villageId` เป็นรหัสหมู่บ้านแขก ไม่ใช่บัญชีหรือสิทธิ์เข้าถึง ขณะนี้ไม่มีเซิร์ฟเวอร์รับเซฟ
- สำเนาเซฟที่อ่านได้ก่อนเขียน เก็บใน `paperbound-village-backup`; ไม่ลบเซฟเก่า v0.6
- ตรวจ revision ก่อนเขียน ปฏิเสธเมื่อพบว่าอีกแท็บเปลี่ยนเซฟแล้ว ให้โหลดล่าสุดก่อน เป็น best-effort local check ไม่ใช่ atomic transaction และไม่ใช่ cloud conflict resolution
- เซฟเสีย/รูปแบบอนาคต: หยุดเขียนทับ; หากมี backup เปิดให้เห็นแบบอ่านอย่างเดียว เซฟเสียยังคงอยู่ การกู้ถาวรยังต้องดำเนินการแยก ไม่กดเริ่มใหม่หากยังต้องการข้อมูลเดิม
- ไม่มีข้อความว่า sync สำเร็จ และไม่มีปุ่ม login หลอก ผู้เล่นเห็นว่าเซฟอยู่ในเบราว์เซอร์นี้เท่านั้น

## v0.8 บัญชี: ขั้นตอนที่ยังต้องทำ
1. เลือก auth provider หลังตรวจความสามารถและค่าใช้จ่ายปัจจุบัน รองรับ Google OAuth และ email OTP
2. กำหนด backend session ที่ตรวจได้จริง และเส้นทาง callback ของ Railway; token/secret อยู่ server variables ไม่อยู่ client bundle
3. สร้างตาราง villages ผูก authenticated owner กับหมู่บ้านหนึ่งหลัง โดย derive owner จาก server session เท่านั้น
4. เพิ่ม GET/PUT save พร้อม revision compare-and-swap แบบ atomic ในฐานข้อมูล; conflict ตอบ 409 โดยไม่เขียนทับ
5. Import เซฟแขกผ่าน preview ให้ยืนยันเมื่อบัญชีมีหมู่บ้านอยู่แล้ว ไม่ auto overwrite
6. Backup/recovery และ migration บนเซิร์ฟเวอร์; ทดสอบสองบัญชีไม่เห็นเซฟกัน สองอุปกรณ์ไม่ทับกัน และ logout ไม่รั่วข้อมูลบัญชีเดิม
7. กำหนด retry/offline pending UI อย่างชัดเจนก่อนแสดงคำว่า cloud saved

v0.7 ไม่เปิดใช้ login/Google/อีเมลหรือ cloud save; เป็นการเตรียมข้อมูลและประสบการณ์ก่อนเชื่อมบัญชี ไม่ให้ผู้เล่นเข้าใจผิดว่าล้างข้อมูลเบราว์เซอร์แล้วกู้จากบัญชีได้
